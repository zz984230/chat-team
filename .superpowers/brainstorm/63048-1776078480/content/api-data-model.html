API 与数据模型

REST API 端点 + WebSocket 事件 + 数据存储结构

REST API 端点

API Endpoints
会话管理
  POST   /api/sessions              创建新会话（提交需求）
  GET    /api/sessions              列出所有会话
  GET    /api/sessions/{id}         获取会话详情
  POST   /api/sessions/{id}/pause   暂停会话
  POST   /api/sessions/{id}/resume  恢复会话
  POST   /api/sessions/{id}/cancel  取消会话

Agent 管理
  GET    /api/agents                列出可用 Agent 定义
  GET    /api/agents/{id}           获取 Agent 详情

工作流
  GET    /api/sessions/{id}/workflow    获取工作流状态
  GET    /api/sessions/{id}/phases      获取各阶段详情
  GET    /api/sessions/{id}/outputs     获取产出文件列表
  GET    /api/sessions/{id}/outputs/{file}  获取具体产出内容

WebSocket
  WS     /ws/sessions/{id}         实时事件流

WebSocket 事件

WS Event Types (Server → Client)
// 会话级别事件
session:created       会话创建
session:started       工作流开始执行
session:completed     工作流完成
session:failed        工作流失败
session:paused        会话暂停
session:cancelled     会话取消

// 阶段级别事件
phase:started         某阶段开始 { phase: 1, agents: [...] }
phase:completed       某阶段完成 { phase: 1, outputs: [...] }
phase:failed          某阶段失败 { phase: 1, error: "..." }

// Agent 级别事件
agent:started         Agent 启动 { agent_id, agent_name }
agent:thinking        Agent 思考中 { agent_id, content: "..." }
agent:working         Agent 执行中 { agent_id, tool: "Write" }
agent:output          Agent 产出文件 { agent_id, file: "01-xxx.md" }
agent:completed       Agent 完成 { agent_id, duration_ms }
agent:failed          Agent 失败 { agent_id, error: "..." }

Obsidian Vault 存储

Session Directory Layout
vault/
├── agents/                          # Agent 角色定义
│   ├── 需求分析师.yaml
│   ├── 方案架构师.yaml
│   ├── 资料研究员.yaml
│   └── 方案撰写员.yaml
│
├── sessions/                        # 会话存储
│   └── {session_id}/               # 例: 20260413-153000-abc
│       ├── meta.yaml               # 会话元数据
│       │   (status, mode, created_at,
│       │    phases, agents, config)
│       ├── 00-原始需求.md           # 用户输入
│       ├── 01-需求澄清.md           # Phase 1 产出
│       ├── 02-技术方案.md           # Phase 2a 产出
│       ├── 03-参考资料.md           # Phase 2b 产出
│       └── 04-最终方案.md           # Phase 3 产出
│
└── kanban/                          # 看板状态
    └── active.md                   # 当前活跃任务
